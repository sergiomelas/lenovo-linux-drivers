Summary
EC is confirmed present and standard (ECDT, ports 0x66/0x62).
Every ACPI object that plausibly represents fan control (H_EC.CFAN, H_EC.TFN1/2/3) exists only as an External() forward-declaration — never actually defined in any of the 26 ACPI tables (DSDT + 25 SSDTs) obtained via acpidump -b.
The DPTF fan participant these objects map to (INTC1048) never enumerates on Linux.
The only writable, OS-visible fan interface (cooling_device3-7, ACPI PNP0C0B fan class) has zero observed effect on physical fan behavior — either disconnected or fully overridden by the EC.
Conclusion: real fan control logic on this model is not reachable through any ACPI table exposed to the OS. It's likely resolved via vendor-specific/SMI-level EC firmware logic outside the standard ACPI namespace, which would explain why Windows also has no direct OS-level control and instead relies on Lenovo's own (closed, unreverse-engineered) Vantage-EC channel.
